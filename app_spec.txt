# BOB: Build Orchestration Bot

## Vision

A **generalized, production-ready autonomous coding framework** that can manage multiple projects simultaneously, support any specification format, and provide robust orchestration for long-running AI-assisted development.

BOB takes the excellent foundations from the `autonomous-coding` quickstart and evolves them into a standalone, configurable framework.

## Top 10 Issues with Current Implementation

### Issue #1: Single Project / Hardcoded Spec

**Location:** `autonomous_agent_demo.py:150-158`, `prompts/app_spec.txt`

**Problem:** The spec file `app_spec.txt` lives in the `prompts/` directory and is copied to each project. Only one project can be active at a time. No project management (create, list, switch, delete).

```python
# autonomous_agent_demo.py:150-158
project_dir = args.project_dir
if not str(project_dir).startswith("generations/"):
    if project_dir.is_absolute():
        pass
    else:
        project_dir = Path("generations") / project_dir
```

**BOB Solution:** Multi-project management with `bob project create/list/use/delete`. Each project has its own spec, config, and state.

---

### Issue #2: JSON File Persistence

**Location:** `progress.py:30-31`, `escalation.py:122`, `stuck_detector.py:30`

**Problem:** All state stored in flat JSON files that can't be queried, don't scale, and risk corruption on concurrent access.

```python
# escalation.py:122
self.state_file = project_dir / "harness_logs" / "escalation_state.json"

# stuck_detector.py:30
self.tracker_file = project_dir / "harness_logs" / "progress_tracker.json"

# Feature list
feature_list_path = self.project_dir / "feature_list.json"
```

**BOB Solution:** SQLite database (default) with optional PostgreSQL for scale. Proper transactions, indexes, and queryability.

---

### Issue #3: No Cost Tracking

**Location:** `client.py`, `agent.py`

**Problem:** No tracking of API token usage or costs. Can't see spend per project, session, or feature. No budget limits.

```python
# client.py - No cost tracking anywhere
return ClaudeSDKClient(
    options=ClaudeCodeOptions(
        model=model,
        # ... no cost tracking
    )
)
```

**BOB Solution:** `CostTracker` class that tracks tokens per session, calculates costs, and can enforce budget limits.

---

### Issue #4: Sequential Task Execution

**Location:** `agent.py:388-726`

**Problem:** Main loop processes one feature at a time sequentially. Independent tasks can't run in parallel, making large feature sets slow.

```python
# agent.py:388-726 - Single main loop
while True:
    iteration += 1
    # ... processes ONE feature at a time
    for feature_id in list(still_failing)[:1]:  # Only first failing feature!
        # ...
```

**BOB Solution:** `TaskQueue` with dependency resolution and `run_parallel()` for concurrent execution of independent tasks.

---

### Issue #5: No API / Programmatic Access

**Location:** `autonomous_agent_demo.py`

**Problem:** CLI only. Can't integrate with CI/CD, webhooks, monitoring dashboards, or other automation.

```python
# autonomous_agent_demo.py - CLI only
def main() -> None:
    args = parse_args()
    asyncio.run(run_autonomous_agent(...))

if __name__ == "__main__":
    main()
```

**BOB Solution:** Keep CLI-only but add scriptable output modes (JSON, quiet) for integration with shell scripts and automation.

---

### Issue #6: Limited Observability

**Location:** `progress.py:22-74`

**Problem:** Session logs are basic text files. No structured logging, no metrics export, no event system.

```python
# progress.py:44-48 - Plain text logging
self.log_file = open(self.log_path, "w")
self.log_file.write(f"Session {self.session_num} started at {timestamp}\n")
self.log_file.write(f"Project: {self.project_dir.resolve()}\n")
self.log_file.write("=" * 70 + "\n\n")
```

**BOB Solution:** Structured JSON logging and `bob status` / `bob logs` commands for better CLI-based monitoring.

---

### Issue #7: Hardcoded Model Configuration

**Location:** `escalation.py:27-30`, `autonomous_agent_demo.py:31`

**Problem:** Model names and escalation thresholds are hardcoded. Can't configure per-project.

```python
# escalation.py:27-30
class ModelTier(Enum):
    SONNET = "claude-sonnet-4-5-20250929"  # Hardcoded!
    OPUS = "claude-opus-4-5-20251101"       # Hardcoded!

# escalation.py:109
MAX_ATTEMPTS_PER_MODEL = 3  # Hardcoded threshold
```

**BOB Solution:** Configurable models and thresholds in `project.yaml`. Different projects can use different models.

---

### Issue #8: Tightly Coupled Prompts

**Location:** `prompts/coding_prompt.md:86-148`

**Problem:** Prompts reference specific application details (OpenROAD, Docker containers). Can't reuse for different project types.

```markdown
# coding_prompt.md:86-148 - OpenROAD specific!
### CRITICAL PRIORITY: REAL EXECUTION INFRASTRUCTURE
**1. Docker Container Setup:**
docker pull openroad/orfs:latest
docker run --rm openroad/orfs:latest openroad -version
```

**BOB Solution:** Template engine with project variables (`{project.name}`, `{project.tech_stack}`). Generic prompts with project-specific injection.

---

### Issue #9: No Checkpointing / Resume

**Location:** `agent.py:476-481`

**Problem:** Sessions run to completion or error. Can't checkpoint mid-session. Context lost on interruption.

```python
# agent.py:476-481 - No checkpointing
try:
    async with client:
        status, response = await run_agent_session(client, prompt, project_dir, logger)
finally:
    logger.stop()
# Session ends, no checkpoint saved
```

**BOB Solution:** `CheckpointManager` that saves conversation state periodically. Can resume from any checkpoint.

---

### Issue #10: Duplicate Stuck Detection Systems

**Location:** `stuck_detector.py` vs `escalation.py`

**Problem:** Two overlapping stuck detection systems that can conflict.

```python
# agent.py:326-331 - Old-style check
is_stuck, report = check_if_stuck(project_dir)  # stuck_detector.py

# agent.py:699-709 - Checks both systems
if result["is_stuck"]:
    esc_summary = escalation_controller.get_escalation_summary()
    if esc_summary["features_stuck"] == 0:
        # Conflict - one says stuck, other says not
        print("[Info] Old stuck detector triggered, but escalation system may have options...")
```

**BOB Solution:** Unified `ProgressController` that combines session tracking, feature attempts, and escalation state into one coherent system.

## Core Concepts

### 1. Projects

A **Project** is an isolated workspace with its own:
- Specification (what to build)
- Tasks (units of work)
- Configuration (models, security, prompts)
- State (progress, escalation, research)

```python
@dataclass
class Project:
    id: str                      # Unique identifier (slug)
    name: str                    # Human-readable name
    description: str             # What this project is
    workspace_dir: Path          # Where files live
    spec_source: SpecSource      # Where tasks come from
    config: ProjectConfig        # Project-specific settings
    created_at: datetime
    status: ProjectStatus        # active, paused, completed, failed

    # Statistics
    total_tasks: int
    completed_tasks: int
    failed_tasks: int
```

### 2. Spec Sources (Pluggable)

```python
class SpecSource(ABC):
    """Abstract base for specification sources."""

    @abstractmethod
    async def fetch_tasks(self) -> list[TaskSpec]:
        """Fetch task specifications from the source."""
        pass

    @abstractmethod
    async def sync(self) -> SyncResult:
        """Sync with source, detecting changes."""
        pass

    @abstractmethod
    async def mark_completed(self, task_id: str) -> None:
        """Notify source that task is complete."""
        pass

# Implementations
class FileSpecSource(SpecSource):
    """Load tasks from a local file (YAML, JSON, Markdown)."""

class GitHubIssuesSource(SpecSource):
    """Load tasks from GitHub issues with specific labels."""

class JiraSource(SpecSource):
    """Load tasks from Jira tickets."""

class LinearSource(SpecSource):
    """Load tasks from Linear issues."""

class APISource(SpecSource):
    """Load tasks from a REST API endpoint."""
```

### 3. Tasks (Generalized Features)

```python
@dataclass
class Task:
    id: str                      # Unique task ID
    project_id: str              # Parent project
    spec_id: str                 # ID from source system

    # Definition
    title: str
    description: str
    acceptance_criteria: list[str]
    steps: list[str]             # Implementation hints

    # Dependencies
    depends_on: list[str]        # Task IDs
    blocks: list[str]            # Tasks blocked by this

    # Metadata
    priority: int                # 1 (critical) to 5 (nice-to-have)
    category: str                # functional, test, infra, docs
    labels: list[str]

    # State
    status: TaskStatus           # pending, in_progress, completed, failed, blocked, decomposed
    assigned_agent: str | None   # Which agent type is working on it
    current_model: str           # Model being used

    # Tracking
    attempts: int
    last_attempt_at: datetime | None
    completed_at: datetime | None

    # Escalation
    escalation_tier: int         # 0=sonnet, 1=opus, 2=diagnosed
    failure_type: str | None
    error_history: list[dict]

    # Decomposition
    parent_task_id: str | None   # If decomposed from another task
    sub_task_ids: list[str]      # If decomposed into sub-tasks

    # Research-First Support
    research_required: bool      # True if task needs research before implementation
    research_complete: bool      # True after research has been done
    research_queries: list[str]  # Suggested queries for Perplexity/web search
    research_findings: str | None  # Documented research results
```

### 5. Escalation Model (from autonomous-coding)

BOB's escalation system is ported directly from the improved `autonomous-coding` implementation. This is the **default behavior** that BOB inherits.

**Source:** `~/work/PhysicalDesign/claude-quickstarts/autonomous-coding/escalation.py`

#### Model Tiers

```python
class ModelTier(Enum):
    SONNET = "claude-sonnet-4-5-20250929"  # Fast, cost-effective
    OPUS = "claude-opus-4-5-20251101"       # More capable, for hard problems
```

#### Failure Types

```python
class FailureType(Enum):
    UNKNOWN = "unknown"
    TOO_BIG = "too_big"           # Feature too complex -> Decompose
    MISSING_INFO = "missing_info" # Knowledge gaps -> Research
    WRONG_INFRA = "wrong_infra"   # Missing packages -> User intervention
    BAD_ASSUMPTIONS = "bad_assumptions"  # Wrong approach -> Research + restructure
    NEEDS_RESEARCH = "needs_research"    # Specific research needed
    DEPS_NOT_MET = "deps_not_met"        # Dependencies not satisfied
```

#### Escalation Actions

```python
class EscalationAction(Enum):
    CONTINUE = "continue"           # Keep trying with current model
    ESCALATE_MODEL = "escalate_model"  # Switch to Opus
    DIAGNOSE = "diagnose"           # Run root cause analysis
    DECOMPOSE = "decompose"         # Break into sub-tasks
    RESEARCH = "research"           # Research mode (Perplexity/web)
    REQUEST_USER = "request_user"   # Stop and ask for help
    RESTRUCTURE = "restructure"     # Research and restructure
    SKIP = "skip"                   # Skip (deps not met or decomposed)
```

#### Per-Task Escalation State

Each task tracks its own escalation state:

```python
@dataclass
class TaskEscalationState:
    task_id: str
    current_model: ModelTier = ModelTier.SONNET
    attempts_at_current_model: int = 0
    total_attempts: int = 0
    failure_type: FailureType | None = None
    diagnosis_done: bool = False
    research_queries: list[str] = field(default_factory=list)
    error_history: list[dict] = field(default_factory=list)
    decomposed: bool = False
    sub_task_ids: list[str] = field(default_factory=list)
```

This state persists across sessions and is used to determine the next action.

### 7. Cost Tracking

```python
@dataclass
class CostTracker:
    """Track API costs per project/session."""

    # Pricing (per 1M tokens)
    PRICING = {
        "claude-sonnet-4-5-20250929": {"input": 3.0, "output": 15.0},
        "claude-opus-4-5-20251101": {"input": 15.0, "output": 75.0},
    }

    def calculate_cost(
        self,
        model: str,
        input_tokens: int,
        output_tokens: int,
        cache_read_tokens: int = 0,
    ) -> float:
        """Calculate cost in USD."""
        prices = self.PRICING.get(model, {"input": 5.0, "output": 20.0})

        # Cache reads are 90% cheaper
        effective_input = input_tokens - cache_read_tokens + (cache_read_tokens * 0.1)

        input_cost = (effective_input / 1_000_000) * prices["input"]
        output_cost = (output_tokens / 1_000_000) * prices["output"]

        return input_cost + output_cost

    async def get_project_costs(self, project_id: str) -> ProjectCosts:
        """Get cost breakdown for a project."""
        return ProjectCosts(
            total_usd=45.67,
            by_model={
                "claude-sonnet-4-5-20250929": 32.10,
                "claude-opus-4-5-20251101": 13.57,
            },
            by_agent={
                "coding": 38.00,
                "research": 4.50,
                "diagnosis": 3.17,
            },
            by_day=[
                {"date": "2026-01-10", "cost": 23.45},
                {"date": "2026-01-11", "cost": 22.22},
            ]
```

## Research-First Architecture

One of the key innovations from the autonomous-coding framework is the **research-first pattern** - allowing tasks to be marked as requiring research before implementation attempts.

### Why Research-First?

| Problem | Solution |
|---------|----------|
| Agent wastes attempts on known-hard problems | Pre-mark tasks for research |
| Reactive research only after failures | Proactive research before coding |
| No guidance on what to research | Spec provides suggested queries |
| Research findings lost between sessions | Persist findings in task state |

### Research Detection in Specs

**YAML Spec with Research:**
```yaml
tasks:
  - id: timing-optimization
    title: Extreme Timing Closure
    description: |
      Achieve timing closure on design with 5.3x clock violation.
      REQUIRES RESEARCH on advanced ECO techniques.
    research_required: true
    research_queries:
      - "OpenROAD timing-driven placement techniques"
      - "buffer insertion algorithms for timing closure"
      - "iterative ECO flow vs single-pass optimization"
    steps:
      - Research optimization strategies
      - Implement best approach from research
      - Verify timing improvement
```

**Auto-Detection Keywords:**
When parsing specs, BOB detects research requirements via keywords:
- `REQUIRES RESEARCH`, `NEEDS RESEARCH`, `DO RESEARCH`
- `research first`, `research before implementing`
- `investigate`, `explore options`, `find best approach`
- `use perplexity`, `web search needed`

### Research State Machine

### Research Engine: Perplexity + Web Search

BOB uses **Perplexity** as the primary research engine, with web search as a fallback.

**Setup:**
```bash
# Set Perplexity API key (required for Perplexity MCP)
export PERPLEXITY_API_KEY=your_api_key_here
```

**Research Tools (priority order):**

1. **Perplexity MCP Plugin** (preferred) - If available via Claude Code plugin system
   - `perplexity_research` - Deep research on complex topics
   - `perplexity_ask` - Quick questions
   - `perplexity_search` - Web search with AI summarization
   - `perplexity_reason` - Reasoning through problems

2. **Web Search** (fallback) - Built-in Claude Code web search
   - Used when Perplexity is unavailable
   - Less structured but always available

**Configuration:**
```yaml
# project.yaml
research:
  engine: perplexity  # perplexity | websearch | both
  perplexity:
    api_key: ${PERPLEXITY_API_KEY}
    mcp_server:
      command: npx
      args: [-y, "@perplexity-ai/mcp-server"]
  fallback_to_websearch: true
```

### Research Workflow

```python
class ResearchController:
    """Manages research-first task flow."""

    def __init__(self, config: ResearchConfig):
        self.config = config
        self.perplexity_available = self._check_perplexity()

    def _check_perplexity(self) -> bool:
        """Check if Perplexity API key is configured."""
        return bool(os.environ.get("PERPLEXITY_API_KEY"))

    async def should_research(self, task: Task) -> bool:
        """Check if task needs research before implementation."""
        return task.research_required and not task.research_complete

    async def run_research(self, task: Task) -> ResearchResult:
        """
        Execute research phase for a task.

        1. Use suggested queries from task.research_queries
        2. Search with Perplexity (preferred) or web search (fallback)
        3. Document findings
        4. Mark research_complete = True
        """
        findings = []

        for query in task.research_queries:
            if self.perplexity_available:
                # Use Perplexity MCP tools
                result = await self.perplexity_research(query)
            else:
                # Fallback to web search
                result = await self.web_search(query)
            findings.append(result)

        # Persist findings
        task.research_findings = self.summarize_findings(findings)
        task.research_complete = True

        return ResearchResult(
            task_id=task.id,
            queries=task.research_queries,
            findings=task.research_findings,
            engine_used="perplexity" if self.perplexity_available else "websearch",
        )

    async def get_implementation_context(self, task: Task) -> str:
        """
        Build implementation prompt including research context.

        If task has research findings, inject them into the coding prompt.
        """
        if task.research_findings:
            return f"""
## Research Findings (apply these to your implementation)

{task.research_findings}

## Task Requirements
{task.description}
"""
        return task.description
```

### Benefits of Research-First

1. **Proactive vs Reactive**: Research happens before wasted implementation attempts
2. **Guided Research**: Spec authors provide domain-specific queries
3. **Knowledge Persistence**: Findings survive across sessions
4. **Cost Efficiency**: Avoid expensive Opus escalations for research-solvable problems
5. **Better Solutions**: Research-backed implementations often superior to trial-and-error
