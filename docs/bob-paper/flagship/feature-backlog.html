A. Experiment infrastructure

The "make the ablation runnable" layer.

IdFeature PriorityTests
F-101 BOB3_ABLATION_MODE switch
Env var plus CLI flag flipping V−1 / V0 / V1 / V2 / V3 as a unit; each maps to a frozen config struct controlling skills, MCP plugins, verification depth, registry writes, confidence decay, RCA gating, regression cascade. 		Block H1H6
F-102 Uniform predicted-confidence elicitor
Post-spawn lightweight LLM probe (src/bob3/calibration_probe.py) that runs identically in every variant. Only fair way to compute ECE across V0 and V3. 		Block H2
F-103 Spec perturbation generator
Deterministic, seedable transforms: P_rename, P_reorder, P_redherring. Round-trip identity at seed=0. 		Block H6
F-104 Reward-hacking detector
Post-hoc LLM-judge with a 5-attack Jain rubric (LRU-injection, site-customize.py hijack, try/except swallow, test-impl coupling, hardcoded I/O). Validated on hand-labels; precision ≥ 0.85, recall ≥ 0.80 before deployment. 		Block H3
F-105 Unified telemetry exporter
run.jsonl per run with a fixed schema (variant, spec, seed, completion, cost, turns, predicted_confidence, task_class, hack_detections, registry_hits, regression_flips, ...). 		Block all H
F-106 Sweep orchestrator
tools/sweep.py consumes a run-plan (variant × spec × seed grid), dispatches cells in parallel, enforces a hard cost-budget guard rail, resumable via resource_checkpoints. 		Block
F-107 External baseline runners
tools/run_aider.py and tools/run_claude_code.py emitting the F-105 schema. Same sandbox, same spec format. 		Strong H1
F-108 Hermetic per-run containerisation
Every run in a fresh Docker container with a pinned base image, no cross-run state outside the explicit registry / checkpoint files. 		Block
F-109 Model and SDK version pinning
Hard-pin claude-code-sdk and the model id; record both in every telemetry line. 		Block
F-110 Reproducibility bundle
bob3 export-bundle <feature> emits a tarball with spec, transcript, diff, telemetry, env lockfile - one command to give a reviewer. 		Strong

B. New verification primitives

DSL criteria that make the showcase demos (D1 nanoGPT, D2 WASM, D3 Navier-Stokes) legible to the verifier and resistant to reward hacking.

IdFeature PriorityTests
F-111 external_match: criterion
Diff bob's output against a versioned external artifact (Karpathy loss CSV, Ghia 1982 tables, WASM-spec test-suite SHA). 		Block D1-D3
F-112 convergence_order_at_least: criterion
Run a numerical solver at N grid resolutions, fit the slope, assert order ≥ X. Reuses design from paper-planning/bob-for-hpc/03-verification-harness.md. 		Block H3D3
F-113 forbidden_imports: criterion
Banlist (e.g. transformers, torch.autograd) - closes the "delegate to a library" reward-hack on D1 and D3. 		Strong H3
F-114 behavioral_signature: criterion
Checks loss-curve shape, not just final scalar. Catches fake training scripts that return the expected number without actually training. 		Strong H3D1
F-115 deterministic_output: criterion
Run with seed=0,1,2,3 - assert identical output. Inherits design from the HPC harness plan. 		Strong
F-116 resource_limit: criterion
Hard caps on wall-clock and peak memory; prevents "let it run forever" gaming. 		Strong
F-117 AST-grade plagiarism detector
Fingerprint generated source against known reference implementations (Karpathy nanoGPT, AMReX kernels, etc.). Flag near-verbatim copies. 		Strong H3D1
F-118 Test - implementation coupling detector
AST flag when tests import internals or share fixtures with implementation in suspicious ways. The "tests pass because tests match the impl bug" defense. 		Strong H3
F-119 Hardcoded-reference-value detector
Flag float literals matching known benchmark values (e.g. Ghia's 0.1147) in source rather than tests. 		Strong H3D3
F-120 Coverage-based hack detector
Reject implementations whose passing tests cover < threshold% of source lines. 		Strong H3
F-121 Property-based test generator
Hypothesis integration. Derive properties from EARS-style unwanted-behavior clauses in the spec - feeds the paper-#2 EARS bridge. 		Stretch
F-122 Differential-testing harness
bob's implementation run side-by-side with a reference implementation on fuzzed inputs; flag any divergence. Essential for D2 (WASM) where 10k spec tests exist. 		Strong H3D2

C. Sandbox upgrades

What the demos require to run at all.

IdFeature PriorityTests
F-123 GPU sandbox
Docker with CUDA or Apple-Silicon MPS, resource caps, pinned drivers. D1 (nanoGPT training) is impossible without it. 		Block D1
F-124 WASM toolchain sandbox
wabt + wasmtime available inside the container for differential testing of D2. 		Block D2
F-125 Scientific-compute sandbox
Pinned NumPy / SciPy / JAX with deterministic BLAS (e.g. OPENBLAS_NUM_THREADS=1). Required for D3 reproducibility. 		Block D3
F-126 Network-egress allowlist
Prevent agents from downloading reference solutions mid-run. The most direct defense against bench leakage. 		Strong H3
F-127 Long-running spawn support
D3 convergence tests run 30+ min; current SDK assumptions break. Audit timeouts, watchdogs, heartbeat semantics. 		Block D3

D. Calibration and decision policy

Use the data bob already collects.

IdFeature PriorityTests
F-128 Per-task-class calibration buckets
bob3 tracks confidence today but doesn't bucket by task type. Needed to compute per-bucket ECE. 		Block H2
F-129 Calibration-aware budget allocator
Actually use the calibration signal to allocate retries. Currently it is recorded but not acted on. The novel mechanism the paper claims is load-bearing. 		Strong H1
F-130 Bayesian confidence aggregator
Combine self-reported confidence + registry-hit rate + AST-complexity heuristic + prior similar-task outcomes into a single calibrated probability. 		Stretch
F-131 Online threshold tuning
Adjust RCA trigger / decomposition depth based on accumulated outcomes. Currently hard-coded constants. 		Stretch
F-132 Per-spec compute-budget cap
max_cost_usd: in the YAML; escalate when hit instead of burning the global budget. 		Strong
