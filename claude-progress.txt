Sync Command Design:

1. **Active Project Resolution**:
   - Try --project flag first
   - Fall back to active project from database
   - Error if no project or multiple active projects
   - TODO: Implement active project tracking in database

2. **Spec Version Tracking**:
   - Currently assumes version 1 for all existing tasks
   - FileSpecSource uses file hash for change detection
   - Future: Track spec_version in Task model
   - Future: More granular change detection per task

3. **Update Strategy**:
   - New: Create Task with status=PENDING
   - Modified: Use update_task_spec() to update spec fields
   - Removed: Use update_task() to set status=DEPRECATED
   - Preserves: status, attempts, assigned_agent, research_complete

4. **Error Handling**:
   - Individual task failures don't halt sync
   - Errors printed but sync continues
   - Summary shows successful vs failed operations
   - Exit code 0 if sync completes, 1 if fatal error

5. **JSON Output**:
   - Tests use regex to extract JSON from mixed output
   - Database migration messages print to stderr
   - Future: Add quiet mode to suppress progress messages
   - JSON contains: project_id, project_name, changes, added, modified, removed

DatabaseManager.update_task_spec():

1. **Separation of Concerns**:
   - update_task(): Execution state (status, attempts, etc.)
   - update_task_spec(): Spec fields (title, description, etc.)
   - Clear distinction prevents accidental overwrites

2. **Dynamic SQL Generation**:
   - Only update provided fields (not None)
   - Build UPDATE statement dynamically
   - Return False if no updates provided
   - Return True if update successful

3. **Field Serialization**:
   - Lists (acceptance_criteria, steps, etc.) → JSON
   - Booleans (research_required) → 0/1
   - Strings and other types → as-is


   Core Components:
   - ClassificationResult: Dataclass for classification results
   - Pattern matching for error classification:
     * INFRASTRUCTURE_PATTERNS: Missing modules, commands, permissions
     * COMPLEXITY_PATTERNS: Timeouts, recursion, circular dependencies
     * MISSING_INFO_PATTERNS: Unknown attributes, API mismatches
     * BAD_ASSUMPTIONS_PATTERNS: Assertions, type errors, key errors

   Key Functions:
   - classify_by_patterns(errors): Pattern-based classification
   - check_repeated_errors(error_history): Detect repeated errors
   - analyze_task_complexity(task): Analyze task complexity
   - classify_failure(task, error_history, deps_status): Comprehensive classification
   - generate_diagnosis_prompt(task, error_history, classification): Generate LLM prompt
   - _generate_research_queries(errors, error_type): Generate research queries

   Classification Categories:
   - TOO_BIG: Task needs decomposition
   - MISSING_INFO: Missing documentation/APIs, needs research
   - WRONG_INFRA: Missing packages/tools, needs user intervention
   - BAD_ASSUMPTIONS: Wrong approach, needs restructure
   - NEEDS_RESEARCH: Specific technical issue, needs research

   Decision Logic:
   1. Infrastructure errors → WRONG_INFRA (highest priority)
   2. Repeated errors → BAD_ASSUMPTIONS (escalate)
   3. Pattern match + complexity → TOO_BIG (decompose)
   4. Pattern match → Use pattern result
   5. High complexity → TOO_BIG
   6. Unclassified errors → NEEDS_RESEARCH
   7. No errors → MISSING_INFO
