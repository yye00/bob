TECHNICAL NOTES:
=================================================================

SpecSource Architecture Design:

1. **Abstract Base Class Pattern**:
   - All spec sources inherit from SpecSource ABC
   - Three abstract methods must be implemented
   - Base class provides common infrastructure (last_sync, version tracking)

2. **TaskSpec vs Task Model**:
   - TaskSpec: Lightweight spec-level representation (immutable from source)
   - Task (from models.py): Database model with execution state
   - Conversion happens during import/sync
   - TaskSpec includes spec_version for change detection

3. **Registry Pattern**:
   - Scheme-based registration (file://, github://, jira://)
   - Factory method creates instances from URIs
   - Global singleton for convenience
   - Type-safe validation on registration
   - Auto-registration on import

4. **Async-First Design**:
   - All SpecSource methods are async
   - Supports network I/O without blocking
   - pytest-asyncio for testing

5. **Change Detection Strategy**:
   - sync() takes dict of known tasks (spec_id -> version)
   - Compares with current state
   - Returns SyncResult with changes
   - Caller decides how to handle changes
   - File hash optimization avoids re-parsing

FileSpecSource Implementation:

1. **Format Support**:
   - YAML via PyYAML (safe_load)
   - JSON via json module
   - Extension-based detection (.yaml, .yml, .json)

2. **Task Parsing**:
   - Required fields: id, title, description
   - Optional fields with sensible defaults
   - Validates data types
   - Clear error messages

3. **Research Detection**:
   - 8 keyword patterns
   - Case-insensitive
   - Scans title, description, steps
   - Auto-sets research_required flag
   - Respects explicit flag if set

4. **Hash-Based Change Detection**:
   - SHA256 of file contents
   - Caches last hash
   - Avoids re-parsing if unchanged
   - Still checks task versions for modifications

5. **Error Handling**:
   - Specific exceptions for each error type
   - Wraps in SpecSourceError
   - sync() returns errors in result
   - Doesn't crash on partial failures

USAGE EXAMPLES:
=================================================================

Using FileSpecSource:

```python
from bob.spec_sources import FileSpecSource, get_registry

# Method 1: Direct instantiation
source = FileSpecSource("file://./spec.yaml")

# Method 2: Via registry
registry = get_registry()
source = registry.create("file://./spec.yaml")

# Fetch all tasks
tasks = await source.fetch_tasks()
print(f"Loaded {len(tasks)} tasks")

# Sync with known tasks
known = {"F001": 1, "F002": 2}  # spec_id -> version
result = await source.sync(known)

if result.has_changes:
    print(f"Added: {len(result.added)}")
    print(f"Modified: {len(result.modified)}")
    print(f"Removed: {len(result.removed)}")
else:
    print("No changes detected")
```

Example YAML spec file:

```yaml
spec_version: 1
tasks:
  - id: F001
    title: Implement feature X
    description: Add feature X to the system
    acceptance_criteria:
      - Feature works as expected
      - Tests pass
    steps:
      - Step 1
      - Step 2
    depends_on: []
    priority: high
    category: functional
    labels:
      - backend
      - api
    research_required: false
    deprecated: false
    spec_version: 1

  - id: F002
    title: Investigate best approach
    description: Research the best way to implement Y
    steps:
      - Look into existing solutions
      - Compare options
    depends_on: [F001]
    priority: medium
    # research_required will be auto-detected as true
```
